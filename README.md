### Итоговый проект

## Реализация боевых алгоритмов для пошаговой стратегии (Heroes-like)

# Общее описание проекта

В рамках итогового проекта была реализована серия алгоритмов, обеспечивающих работу боевой логики в пошаговой стратегии. Основная цель проекта — применить классические алгоритмы и структуры данных для решения прикладных задач, возникающих в игровой логике.

Разработанные компоненты взаимодействуют с готовым игровым движком через заданные интерфейсы и не изменяют его внутреннюю реализацию, что соответствует условиям задания.

## Реализованные компоненты и алгоритмы
1. Формирование армии компьютера

# GeneratePreset.generate(...)

Данный метод отвечает за автоматическое формирование армии компьютера на основе доступных типов юнитов и ограничения по очкам.

При построении армии учитываются следующие условия:

- суммарная стоимость армии не превышает заданное значение maxPoints;

- количество юнитов каждого типа ограничено (не более 11);

- выбор юнитов производится на основе их эффективности.

# Критерием эффективности является:

- отношение базовой атаки к стоимости;

- при равенстве — отношение здоровья к стоимости.

# Армия формируется пошагово: на каждом шаге выбирается наиболее выгодный доступный тип юнита с учётом оставшихся очков и действующих ограничений.

## Оценка сложности:

- на каждом шаге производится анализ списка типов юнитов — O(n);

- количество шагов ограничено числом добавленных юнитов — O(m).

## Итоговая сложность:
O(n · m),
где n — количество типов юнитов,
m — размер формируемой армии.

## 2. Симуляция пошагового боя

# SimulateBattle.simulate(...)

Метод реализует пошаговую симуляцию боя между армией игрока и армией компьютера.

Ключевые особенности логики боя:

- бой разделён на раунды;

- в каждом раунде все живые юниты обеих сторон формируют общую очередь ходов;

- порядок ходов определяется значением базовой атаки (по убыванию);

- каждый ход сопровождается логированием;

- бой корректно завершается при отсутствии возможных атак или при уничтожении одной из сторон.

- Реализация учитывает динамическое изменение состава армий (гибель юнитов) и корректно обрабатывает ситуацию, когда дальнейшие атаки невозможны.

## Оценка сложности:

- формирование и сортировка очереди ходов — O(n log n) за раунд;

- количество раундов ограничено числом действий юнитов.

## Итоговая сложность:
O(n² log n), где n — общее количество юнитов, участвующих в бою.

### 3. Определение доступных для атаки юнитов

## SuitableForAttackUnitsFinder.getSuitableUnits(...)

- Метод определяет, какие юниты могут быть атакованы в текущий момент времени.

## Юнит считается доступным для атаки, если:

- он жив;

- перед ним отсутствует другой живой юнит со стороны направления атаки.

Для ускорения проверок используется структура HashSet, в которой хранятся координаты занятых клеток поля боя.

# Оценка сложности:

- сбор информации о юнитах — O(n);

- проверка доступности для атаки — O(n).

## Итоговая сложность:
O(n), где n — количество юнитов на поле.

### 4. Поиск пути к цели

## UnitTargetPathFinder.getTargetPath(...)

Метод определяет кратчайший путь между атакующим юнитом и его целью на игровом поле.

Особенности реализации:

поле рассматривается как граф фиксированного размера;

допускаются перемещения в 8 направлениях, включая диагонали;

клетки, занятые живыми юнитами, считаются препятствиями;

для поиска пути используется алгоритм A* с допустимой эвристикой (Chebyshev distance).

Алгоритм гарантирует нахождение кратчайшего пути либо корректно сообщает об его отсутствии.

Оценка сложности:

поиск пути в графе размером W × H с использованием приоритетной очереди.

Итоговая сложность:
O(W · H · log(W · H)),
где W и H — размеры игрового поля.
